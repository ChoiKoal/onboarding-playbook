Hereby Med 병원 온보딩 플레이북 v1.0

신규 병원 도입 표준 절차 — 계약부터 전 직원 가동·안정화까지 · 작성: KOAL (PM) · 2026-07-25 · 근거: 1호 도입 병원 실사례(2026.07)

목적. 병원 1곳의 Hereby Med 도입을 예측 가능한 4~6주 절차로 표준화한다. A병원(1호 도입, 직원 약 300명 규모)에서 검증된 순서·체크리스트·역할 분담·주의점을 담았다. 목표는 "도입 3개월 → 4~6주", 그리고 30~50개 병원 확장 시에도 같은 품질로 반복하는 것이다.

P0 계약·킥오프D-30 ~ D-21

P3 실무진 검증D-7 ~ D-1
P4 전 직원 전파D ~ D+7
P5 안정화D+7 ~ D+30

A병원 실측: 실무진 시연(7/21) → 수정본 납품(7월 말) → 8월 급여 병행 테스트 → 9월 중순 전체 가동. B병원(2호) 적용: 1주차 소개 → 2주차 계약 → 3주차 데이터 투입.

2. Phase 1 — 데이터 수집 (D-21 ~ D-14)

세팅 품질은 데이터 최신성이 좌우한다. 수집 시점은 "세팅 직전 최신 갱신본" — 미리 받아두면 입퇴사로 금방 낡는다(A병원 교훈: 8월 갱신본으로 재수집).

병원 제공 데이터 체크리스트

  • 조직도 — 부서 > 팀 > 직군(간호사/간호조무사/요양보호사/이송지원 등) 3~4단계 트리. 시스템은 사실상 무제한 깊이 지원
  • 직원 명부(엑셀) — 성명·주민번호 또는 생년월일·연락처(임시비번 문자 발송용)·입사일·소속·직군·근무 그룹. 이메일은 선택(없는 직원 다수 전제)
  • 급여 관리 대장(엑셀 원본) — 암호 포함 원본 그대로. 시트 구조·수식·계산 관행이 세팅의 정본 원천 (1호 병원 = 47시트 워크북)
  • 급여 계산 기준 문서 — 워크북 안의 서술형 기준("급여특이사항" 시트 등)도 반드시 포함 — 수당 환산 규칙의 유일한 원천인 경우가 많음
  • 휴가 체계 — 사용 중인 휴가 유형 전체(시간 단위 연차 포함), 유형별 차감 규칙, "조퇴" 등 병원 고유 용어. 3교대 적용 제외 유형 명시
  • 근무 유형/교대 체계 — 상근/3교대 구분, 병동별 듀티(D/E/N), 1일 소정근로시간(상근 8h vs 교대 12h — 반차 파생 시간이 달라짐)
  • 간호인력 배치 계산 수식 — 직군별(간호사/조무사/요양보호사/병동지원/재활지원) × 병동별 비율 기준 (공단 신고·삭감 판정 기준)
  • 계약서·문서 템플릿 — 근로계약서, 재직증명서 등 (전자서명 템플릿 등록용)
  • 호봉표 — 직군별(간호부/기능직 등)
  • 공휴일 운영 방침 — 병원 지정 휴일, 공휴일 정상 근무 처리 여부
주의. 개인정보 파일은 반드시 암호화 전달(비밀번호 별도 채널). 개인명이 파일·시트명에 노출된 자료(예: 정산 시트)는 취급 주의.

4. Phase 3 — 실무진 검증 (D-7 ~ D-1)

  • 현장 시연 미팅(반나절): 전 메뉴를 실무진 눈으로 통과. 요구·버그는 그 자리에서 기록 → K/O/D/A 회의록 + 백로그 등록
  • 병행 테스트: 직전/당월 급여를 엑셀과 Hereby에서 이중 계산해 대사(A병원 = 도입 익월 급여). 급여 시트 → 근태 → 휴가 → 결재 순으로 시나리오 검증 (PM이 UAT 시나리오 제공)
  • 피드백 루프: 수집 → PM 스코어링 → FIG 반영. A병원 실측: 요구 13건 중 8건이 1~3일 내 반영 — 루프가 빠르므로 수집 품질이 병목
  • 계정 점검: 실무진 로그인 전수 확인(A병원에서 로그인 불가 이슈 반복), 비밀번호 찾기 플로우 시연

8. 1호 병원 도입에서 배운 것 (Lessons Learned)

교훈내용 → 플레이북 반영
3교대는 별개 세계휴일 개념 없음(오프 수만큼 휴무), 시간 단위 연차 불가, 반차 파생 시간 상이(12h). 근태·휴가 세팅 전에 교대 체계부터 파악 → P1 체크리스트
엑셀 관행이 요구사항의 원천"작성 중/완료" 셀 색칠, 부서별 시트 분할, 퇴사자 별도 관리 등 — 엑셀 원본을 받으면 요구사항의 80%가 그 안에 있다 → 원본 워크북 필수 수집
수식 없는 납품은 검증 불가실무진은 합계가 넘어가는지로 신뢰를 판단. 수식 미적용 시연은 "잘 모르겠다"로 끝남 → P2 게이트
이메일 없는 직원 다수전자계약·계정 전파 모두 문자(SMS) 기반으로 설계 → P4
비밀번호 = 최대 민원분실 민원이 관리자 업무를 잠식 — 셀프 찾기(전화번호) 플로우를 전파 전에 검증 → P3
공단 신고가 킬러 유스케이스간호인력 비율(실입원 환자 수 기준)·근무표 인쇄 제출 — 요양·재활병원 공통 니즈, 세일즈 포인트로 활용 → P1 수식 수집
데이터는 세팅 직전에입퇴사 변동이 잦아 미리 받은 명부는 낡는다 → P1 시점 원칙
대면 계약이 기본고령 직원 비중 높음 — 전자서명은 태블릿 대면 모드 중심으로 준비 → P2 템플릿
